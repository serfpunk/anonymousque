# Anonymousque Neon — бот анонимных вопросов и рассылки

Обновление проекта `serfpunk/anonymousque`: один бот для многих креаторов, личный ответ автору и необязательная публикация вопроса и ответа в канале. Вопросы и ответы: текст, фото, голосовые. Публикация — два отдельных сообщения. Поддержаны блокировка отправителя, простое ограничение частоты, кабинет и список последних 10 неотвеченных вопросов.

## Как это работает

1. Креатор открывает `/start`, получает персональную ссылку и размещает её в канале.
2. Подписчик переходит по ссылке и отправляет вопрос. Креатор получает новое сообщение бота, без имени и профиля отправителя, а не пересылку.
3. Креатор нажимает «Ответить» и отправляет текст, фото или голосовое. Бот сохраняет ответ и пытается доставить его автору. При неудаче доступна повторная отправка.
4. При желании креатор нажимает «Опубликовать вопрос и ответ». Для этого канал нужно предварительно подключить. Бот проверяет права креатора и свои права администратора при подключении и публикации.

### Анонимность и безопасность

Анонимность **от креатора**, а не от Telegram или владельца сервиса. Telegram ID отправителя, вопросы и ответы хранятся в PostgreSQL, пока владелец сервиса их не удалит. Автоматического срока удаления или пользовательской команды удаления в этой версии нет. Не передавайте базу третьим лицам, ограничьте доступ к ней, включите резервные копии и заранее определите правила хранения/удаления. Пользователь получает предупреждение до отправки, в том числе о возможной публикации. Текст вопроса, фото или голос могут сами раскрыть личность. Не обещайте полную анонимность.

Файлы не копируются на диск приложения: сохраняется Telegram `file_id`. Telegram и владелец сервиса имеют доступ к соответствующим данным в рамках работы бота. Кнопки действий проверяют, что вопрос принадлежит этому креатору. Текст не обрабатывается как HTML, а входящие сообщения не пересылаются. Блокировка скрывает личность отправителя от креатора. Ограничение частоты работает на пару отправитель–креатор, но не заменяет полноценную антиспам-систему.

## Neon: бесплатный PostgreSQL

- Создайте проект на бесплатном тарифе Neon, регион — как можно ближе к серверу. До создания ознакомьтесь с политикой хранения данных и применимыми требованиями к персональным данным. Выберите прямую (direct, не pooled) строку подключения: проект создаёт схему при старте и во время импорта. Не отправляйте строку подключения в чат или GitHub: она содержит пароль.
- Установите эту строку целиком в `DATABASE_URL` в Timeweb. Для Neon `asyncpg` использует проверку TLS-сертификата и имени сервера через системные сертификаты. `asyncpg` не поддерживает параметр `channel_binding` из строки Neon: код исключает этот параметр и выводит предупреждение; проверка TLS при этом остаётся включённой. Сверьтесь с актуальными рекомендациями Neon: https://neon.com/docs/guides/python.
- В простое рассылок worker ждёт события, а не опрашивает базу. Неиспользуемые подключения закрываются через 60 секунд. После пяти минут без запросов Neon может приостановить вычисления; первое подключение после сна может занять больше времени. При временной сетевой ошибке отдельное действие бота может не выполниться — проверьте результат перед повтором. База не гарантирует работу 24/7 на бесплатном тарифе.
- Следите за квотами в Neon: на бесплатном тарифе сейчас заявлены 1 ГБ данных и 100 CU-часов в месяц на проект; при исчерпании вычислений база приостанавливается. Снижение фоновых запросов не гарантирует, что квоты хватит. См. https://neon.com/docs/introduction/plans. Настройте независимые резервные копии.
- **Не запускайте новую версию и не меняйте/не перезапускайте старый контейнер до переноса**. Для сохранения SQLite сначала сделайте согласованную копию и сохраните её за пределами контейнера. Во время переноса обеспечьте остановку записи старого бота. Файл базы содержит персональные данные — используйте только приватную передачу.

## Развёртывание на Timeweb Cloud App Platform

1. Через **@BotFather → /newbot** создайте бота. Сохраните токен в секрете. Не помещайте токен в код, GitHub, чат или скриншоты.
2. Создайте базу PostgreSQL в Neon или у другого провайдера, разрешите приложению подключение и возьмите строку `postgresql://...`. Для Neon используйте прямую строку подключения. Учётной записи нужны права на создание и изменение таблиц. Проверьте тариф и правила хранения данных провайдера.
3. Сохраните резервную копию вашего старого репозитория и, если есть, старого файла SQLite. Загрузите файлы этого проекта в свой GitHub-репозиторий (например, в отдельную ветку). **Не загружайте** `.env`, SQLite и токены. `legacy/main_v1.py` — резервная копия прежнего кода, не запускается в новой версии.
4. Если старые данные нужно сохранить, сначала выполните раздел «Перенос старой базы». Иначе начните с пустой PostgreSQL-базы.
5. В Timeweb Cloud откройте **App Platform → создать приложение → Dockerfile**, подключите репозиторий и выберите нужную ветку и конфигурацию. `Dockerfile` находится в корне.
6. В настройках приложения добавьте переменные окружения `BOT_TOKEN`, `DATABASE_URL`; необязательно — `RATE_LIMIT_SECONDS` (по умолчанию 60). Не используйте значение из `.env.example` как настоящий токен.
7. Выполните деплой. При запуске создаются таблицы. Приложение использует long polling: запускайте **ровно один экземпляр бота с этим токеном**, остановив старый процесс. При старте приложение удаляет существующий webhook, сохраняя ожидающие обновления. Параллельный запуск старой и новой версии одного бота приведёт к конфликтам.
8. Откройте бота и отправьте `/myid`. Скопируйте свой числовой Telegram ID в переменную `ADMIN_IDS` в настройках приложения (несколько ID через запятую), сохраните и выполните новый деплой. После этого команда `/admin` доступна только указанным ID. Пустой `ADMIN_IDS` отключает админку. Не используйте @username вместо числового ID.
9. Проверьте журнал запуска: контейнер не должен перезапускаться. Не публикуйте логи, если они содержат секреты или личные данные.
10. Проверьте с двух Telegram-аккаунтов: регистрацию, ссылку, вопрос, личный ответ, затем подключение тестового канала и публикацию. Проверьте также фото/голосовое, блокировку, ограничения частоты и отказ в доступе чужому вопросу. Канал должен разрешать боту публикации.

Timeweb при повторном деплое создаёт новый контейнер, поэтому SQLite внутри контейнера не является постоянным хранилищем. Используйте отдельную PostgreSQL-базу: https://timeweb.cloud/docs/apps/how-it-works. Переменные окружения: https://timeweb.cloud/docs/apps/variables.

## Админка и рассылки

- `/myid` показывает собственный числовой Telegram ID. `/admin` открывает админку только пользователям из `ADMIN_IDS`. Каждый переход и действие кнопок проверяет ID; не передавайте доступ к аккаунту администратора.
- В статистике: все известные пользователи, активность за 7/30 дней, число креаторов, доставленных вопросов/ответов, количество потенциально доступных адресатов и известные блокировки. Активность — время последнего взаимодействия с ботом, а не посещение Telegram. До установки этой версии история активности неизвестна; старые пользователи не засчитываются в активных до следующего взаимодействия. Блокировка известна только после неудачной доставки.
- В этой версии отдельные настройки отключения или согласия на рассылки отсутствуют: рекламные и сервисные сообщения направляются всем известным пользователям, о блокировке бота которыми неизвестно. Остановить все сообщения можно только через блокировку бота в Telegram; тогда также не придут личные ответы и другие сообщения. При первом старте бот уведомляет о возможности рекламы и сервисных рассылок.
- В админке выберите категорию, введите текст до 3000 UTF-16-единиц, проверьте предпросмотр и предварительное число получателей и подтвердите отправку. Рекламная рассылка автоматически помечается как «Реклама», к каждому сообщению добавляется подсказка об остановке бота в Telegram. Нельзя добавлять фото, кнопки, разметку и файлы; обычные ссылки в тексте можно отправлять. В сервисных уведомлениях не размещайте рекламу.
- Состав получателей фиксируется при подтверждении и не пополняется позже. Перед фактической отправкой известная блокировка проверяется повторно; заблокировавшие бота пользователи исключаются. Новые пользователи, зарегистрированные после постановки в очередь, не получают уже созданную рассылку.
- Очередь, содержимое рассылок и результаты хранятся в PostgreSQL. На карточке и в «Последние рассылки» доступны статус и остановка: доставлено, ошибки, пропущено, ожидание и неопределённый результат. При остановке одно сообщение, отправка которого уже началась, может всё же прийти. Остановленную рассылку нельзя продолжить.
- Очередь восстанавливается после перезапуска. Если сервер упал во время отправки или результат Telegram неоднозначен, запись помечается «результат неизвестен» и **не** отправляется автоматически повторно, чтобы снизить риск дубликата. Точного гарантированного охвата нет. Сообщения обрабатываются с ограничением скорости, а при ограничении Telegram отправка приостанавливается и продолжается.
- Данные пользователей и тексты рассылок хранятся без автоматического удаления. Ограничьте доступ к БД, настройте резервное копирование и срок хранения. Перед рассылкой рекламы проверьте применимые требования к согласию, отзыву согласия, маркировке рекламы и персональным данным. Эта версия не проверяет согласие и сама по себе не гарантирует юридическое соответствие. Не игнорируйте ранее сообщённые пользователями отказы.

## Перенос старой базы SQLite (необязательно)

Используйте только если у вас есть **реальный файл** старой базы `anon_qa_multi.db` или тот, который указывался через `DB_PATH`. Репозиторий содержит код, но не содержит базу пользователей. Если SQLite хранилась только внутри удалённого контейнера, данные могут быть недоступны. Без копии базы сохранить старые ссылки невозможно.

1. Остановите старого бота. Скопируйте и сохраните резервную копию SQLite. Не выкладывайте её в GitHub.
2. Создайте **пустую** PostgreSQL-базу и настройте доступ к ней с компьютера, где находится копия SQLite. Скрипт откажется импортировать в непустые таблицы и не объединяет существующие данные.
3. Установите зависимости: `python -m pip install -r requirements.txt`.
4. Задайте `DATABASE_URL` в окружении безопасным для вашей ОС способом и выполните `python migrate_sqlite.py /путь/к/anon_qa_multi.db`. На Linux/macOS при наличии локального `.env` можно временно загрузить переменную в текущую оболочку; не публикуйте историю команд и содержимое переменных.
5. Убедитесь, что скрипт сообщил количество записей. Запустите новую версию, используя ту же PostgreSQL-базу и тот же Telegram-бот. Проверьте старые ссылки и тестовый вопрос.

Переносятся креаторы и их коды ссылок, каналы, вопросы и блокировки. После запуска новая версия добавит в статистику известных креаторов и отправителей вопросов; в старой версии история активности не хранилась. Поля старых настроек уведомлений в PostgreSQL, если присутствуют, не используются при рассылках. Старые данные тарифов Free/Pro и даты подписок не используются новой версией. Прежняя база не сохраняла текст ответов — восстановить их нельзя. Пометка уже отвеченных вопросов переносится, но их нельзя повторно опубликовать через новую версию; история отправленных сообщений в Telegram при этом не меняется. Статус доставки старых вопросов достоверно не известен, при импорте они считаются доставленными. Старые кнопки ответов `reply_pm`/`reply_ch` совместимы с новым сценарием: сначала личный ответ, затем публикация по выбору. Также можно найти неотвеченные вопросы через кабинет.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Интеграционные тесты PostgreSQL по умолчанию пропускаются. Чтобы запустить его, укажите `TEST_DATABASE_URL` для отдельной тестовой базы, где разрешено создавать и удалять тестовые схемы, и повторите команду. Тесты не подключаются к Telegram. Для дополнительной проверки сценария админки на имитации Telegram можно выполнить `python tests/admin_e2e.py` с тем же `TEST_DATABASE_URL`.

## Известные ограничения MVP

- Состояния текущего диалога хранятся в оперативной памяти: при рестарте нужно повторить действие или открыть ссылку заново; сами вопросы и ответы остаются в БД.
- Telegram не предоставляет атомарную транзакцию для отправки сообщения и записи её результата в базу. При сбое ровно между этими действиями повторная попытка может создать дубликат. Публикация состоит из двух сообщений; при частичной ошибке повторная попытка продолжает с сохранённого шага, но пограничный сбой может дать дубликат. Проверяйте канал перед повтором.
- Если пользователь заблокировал бота, личный ответ не доставится; креатор может повторить попытку. Публикация не требует успешной личной доставки.
- Пользователь может отправить новый вопрос по ссылке; поддерживаются текст до 3000 символов и подписи к медиа до 800 символов. Нет платежей, веб-панели, групповой модерации, автоматической очистки и полноценной антиспам-защиты.
- Таблицы создаются при старте; для дальнейших изменений схемы нужна отдельная система миграций. Регулярно создавайте и проверяйте резервные копии.
